## 2. 已确认的最新核心口径

以下内容以后不要再被旧文档带回去：

- P0 冷启动保留，但只支持 **GitHub 公开仓库技术画像 + 离线/手工榜单**。
- P0 不支持 Gitee、批量爬取、定时自动更新榜单、长期画像沉淀表。
- P0 技术画像不落核心主库，排行榜可由静态 JSON / 缓存 / 手工维护承载。
- P0 技能标签只使用预置字典，不允许用户自定义。
- P0 中文搜索采用 MySQL FULLTEXT + ngram parser，效果不好时服务层降级 LIKE。
- P0 不实现结项凭证，不进入 DDL、接口与信誉分计算，整体移入 P1。
- P0 不做核心表软删除，不加 is_deleted。
- P0 管理员权限为单级 admin。
- P0 举报对象只开放 user / project，evaluation 争议走 appeal，不走 report。
- P0 不做微信主动推送、完整消息系统、notification 表；替代方案是 `GET /api/me/badges` 未读角标聚合。

## 3. 退出机制最新口径

详细设计 V2.1 已冻结三层结构：

```text
team_member.exit_mode = self_exit / exit_vote
exit_vote.result = pass / reject / NULL
team_member.status = active / exited
```

不要再使用旧文档里的：

```text
有事退出 / 协商退出 / 无故退出 / remove_vote / removed
```

P0 执行规则：

- `self_exit`：成员主动跑路，不投票，直接生效，扣 10 分，`status -> exited`。
- `exit_vote + pass + negotiated`：扣 5 分，`status -> exited`。
- `exit_vote + pass + malicious`：扣 10 分，`status -> exited`。
- `exit_vote + reject`：不扣分，成员保持 active，不写 credit_change。
- 被投票人在投票期间主动 self_exit：走 self_exit 扣分链路，进行中的 exit_vote 关闭，result 保持 NULL。
