- **验收**：三个页面视觉 token 同源；页面渲染前后截图对比无肉眼差异。

### ⛔ 第二批（未授权，禁止开始）

### K3-2 脚本加载优化（B-01）
- **问题**：game.html 7 个 `<script>` 全部 render-blocking（合计 ≈817KB 未压缩）。
- **做法**：仅保留首屏必需的同步脚本；`game-events-expanded.js`、`game-visual.js` 等改 `defer`（若依赖顺序允许）；确认 `loadData` 时序不被破坏（首屏 loading 状态即可）。
- **验收**：首屏 TTI 明显改善；控制台无加载顺序错误。

### K3-3 事件图占位与加载体验（B-02）
- **问题**：事件 `<img class="scene-img">` 无宽高占位，图片加载后页面跳动；大图 0.4~1.3MB 反复拉取。
- **做法**：给 `.scene-img` 设固定 `aspect-ratio` + 背景占位色；同一地点系列事件可复用已加载图（CSS/结构层即可，JS 逻辑由主会话配合）。
- **验收**：事件切换无跳动；弱网截图无明显空白抖动。

### K3-4 通知严格串行（I-2）
- **问题**：toast / 升级通知 / 成就横幅可并行堆叠，任务书要求「同一时间最多一条主通知」。
- **做法**：CSS/结构层把通知容器改为单槽（每次只显示一条，进入/退出动画），排队逻辑由主会话在 JS 侧配合（如需）。
- **验收**：同时触发成就+升级+toast 时页面只显示一条主通知，其余排队。

### K3-5 移动端长内容弹窗（I-1）
- **问题**：图鉴/日记（200 条）在 390×844 / 844×390 下滚动体验未验证、底部操作可能被遮挡。
- **做法**：`.modal-box` 在移动端 `max-height` 与内部滚动区细化；底部按钮固定不随内容滚动；横屏（844×390）专项调整。
- **验收**：两个横竖屏尺寸下弹窗内容可滚到最底、按钮始终可见。

### K3-6 属性面板 buff 来源拆分（D-c 展示层）
- **数据**：主会话会在 `finalStats()` 提供来源拆分字段（基础/装备/称号/技能树/锻造/NPC），你负责渲染。
- **做法**：`openStats` 属性行下方以小字列出各来源贡献（样式优雅、不喧宾夺主）。
- **验收**：玩家一眼看出攻击/防御/生命各来源。

### K3-7 签到 7 天进度条（D-g 展示层）
- **数据**：主会话输出「今日第 X 天 / 明天领 Y / 进度百分比」字段。
- **做法**：签到弹窗做 7 格进度条 + 明天奖励预告。
- **验收**：视觉清晰、移动端不溢出。

### K3-8 reduced-motion 全站一致（G3）
- **问题**：部分 CSS 动画/粒子未跟随 `prefers-reduced-motion`。
- **做法**：全站 CSS 动画统一加 `@media (prefers-reduced-motion: reduce)` 降级；地图粒子容器在 reduce-motion 下停用（CSS 层 `animation: none`，JS 暂停由主会话处理或你改 map.html 内联 JS 中 map 页自己的粒子代码——map.html 可改）。
- **验收**：开启系统减少动态后无大面积动画。

### K3-9 地图粒子性能（J1）
- **问题**：地图背景粒子常驻运行。
- **做法**：map.html 内粒子逻辑：页面不可见（`document.hidden`）或 reduce-motion 时暂停/降频（map.html 的 JS 归你）。
- **验收**：后台标签页 CPU 占用显著下降。

### K3-10 旅行信息展示（F2 展示层）
- **数据**：主会话在旅行确认/结果中提供目的地等级差、耗时、遇险率字段。
- **做法**：旅行弹窗与抵达文案美化（排版、图标、信息层级）。
- **验收**：信息清晰、风格统一。

### K3-11 关系面板加成明细（H3 展示层）
- **数据**：主会话输出每个 NPC 的「当前贡献：攻+X 防+Y 经验×Z」。
- **做法**：`openNpcRelations` 卡片样式：贡献行小字 + 下一档解锁预告。
- **验收**：关系列表信息完整不拥挤。

### K3-12 帮助文案按阶段重排（E7/I5）
- **问题**：帮助页混合新旧系统描述，自动战斗/探索等条目与实际行为不一致。
- **做法**：按「创建/主线/随机/战斗/存档」重排 help 内容与 tab；删除或标注未实现系统；与主会话确认最终文案（帮助页 HTML 归你，文案清单从 E7 调研结论取）。
- **验收**：玩家按 tab 顺序读完即掌握全部真实系统。

### K3-13 NPC 好感阶段专属文案（H2 文案部分）
- **做法**：为 NPC_RELATION_LEVELS 各档写 1 句阶段解锁文案（20 相识 / 50 友善 / 100 信赖 / 200 挚友 / 350 生死之交 / 500 灵魂伴侣），样式显示在关系卡片「下一档解锁」位。
- **验收**：文案与档位数值一致。

### K3-14 标题页/创建流程视觉打磨（A 区延续）
- **问题**：标题页与创建流程（出身/觉醒）视觉层级一般。
- **做法**：标题背景氛围、出身卡选中态、觉醒重摇动效、按钮 hover/focus 态统一打磨（纯 CSS/结构）。
- **验收**：截面前后对比更精致；不改变交互逻辑与按钮 id。
