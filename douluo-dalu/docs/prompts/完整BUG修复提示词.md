# 第一部分：14 条界面与体验 BUG

## BUG #1 觉醒问号未居中

检查 `public/game.html` 中 `.awaken-img-wrap` 与 `.awaken-q`。让“？”在圆盘几何中心与视觉中心都稳定居中，不受字体基线、行高、动画位移和浏览器字体差异影响。可使用绝对定位加 `inset:0`、网格/弹性居中以及经过校正的行高，但不要用只适配单一分辨率的魔法像素值。

验收：Chrome 与 Edge，在 1920×1080、1366×768、1024×768、390×844 下，初始问号都位于圆心；缩放 80%、100%、125% 后不漂移。

## BUG #2 觉醒旋转特效割裂

检查 `.light-rays`、`.magic-circle`、`.altar-ring` 的叠加动画。当前光束使用离散扇区的 `conic-gradient`，容易产生分段感。改为连续柔和的光束层，可使用模糊、渐变透明度、伪元素多层叠加和单一连续旋转；避免同一元素同时由多个动画竞争 `transform`。动画开始和循环边界不能跳帧。

验收：连续观察至少 20 秒无明显回跳、卡顿或扇区硬切；低特效模式与 reduced-motion 下正确降级；不显著提高 CPU 占用。

## BUG #3 觉醒后大圆套小圆

当前 `.awaken-img-wrap img` 为 88% 宽高、圆角并带边框，形成内外双圆。让武魂图像成为圆盘主体：图片覆盖容器，使用 `width/height:100%`、`object-fit:cover`，移除内层独立边框和不必要的内缩；保留外圈法阵与统一光晕。图片加载失败时图标仍居中且美观。

验收：觉醒前是问号圆盘，觉醒后是单一完整武魂圆盘，没有明显套娃边框。

## BUG #4 觉醒页响应式溢出

检查创建角色第三步的完整高度、固定高度、描述区、剩余次数、按钮区以及所有媒体查询。目标是在常见桌面、笔记本、平板和手机视口中完成觉醒无需页面整体上下滚动；内容较长时只能让描述局部滚动。优先使用 `min()`、`clamp()`、`dvh`、网格自适应和紧凑断点，避免固定 360px/96px 组合挤爆 768px 高度。

验收：1366×768、1280×720、1024×768、390×844、844×390 均无横向溢出；关键按钮始终可见可点；刘海/安全区不遮挡。

## BUG #5 主游戏左右空隙过大

检查 `.game-layout` 在宽屏下的 `max-width:1600px`。利用更大可用宽度，同时保持叙事文字的舒适行长。可以让布局最大宽度扩大或铺满，把额外空间分配给状态栏、场景图和辅助留白，但正文文本应设置合理的内部 `max-width`，不能拉成难读的超长行。

验收：1920、2560 宽屏不再出现大片无意义空白；1366 和移动端不回归；中央内容视觉重心稳定。

## BUG #6 开场剧情点击混乱

彻底修复 `playPrologue()`。当前代码仍可能向 `document` 注册点击监听，导致点击穿透和与自动播放定时器竞态。事件只能绑定到序章专用容器或明确的“继续”区域；调用 `preventDefault()` 与 `stopPropagation()`；推进函数必须带锁且幂等；每次手动推进前清除自动定时器；结束时移除所有监听和定时器；空格/Enter 只能在序章激活时生效。

验收：快速连点、按空格、按钮点击与自动播放交替时，每次最多前进一步，不后退、不跳两步、不触发背后按钮；结束后全局不残留监听。

## BUG #7 开场剧情改为视觉小说式

把序章从纯文字升级为 VN 风格：背景图或现有场景资源、半透明墨金文本框、章节/地点提示、逐段文字、明确的“点击继续/自动播放/跳过”反馈。不得引入外部 CDN 或新框架；优先复用现有 `assets/scenes`。背景图失败时必须有渐变兜底，文字对比度符合可读性要求。

验收：序章拥有场景视觉、段落节奏和明确操作；移动端文字不溢出；reduced-motion 下无打字或大幅转场但内容完整。

## BUG #8 武魂专属觉醒故事

为所有武魂提供可用的专属觉醒叙事，而不是只给属性和 `desc`。优先从 `public/data/spirit-events.json`、武魂 `desc/traits/type/tier` 生成或映射结构化三段式内容：异象出现、武魂回应、角色理解。神级/顶级武魂应有更完整演出，但低级武魂也必须有尊重玩家选择的独特故事，不能嘲讽或明显敷衍。

实现为数据驱动函数或字段，不要复制 70 份 UI 逻辑。专属故事应在确认武魂前后自然播放一次，可跳过，旧存档不得被强制重播。

验收：随机抽查至少每个 tier 3 个武魂，文本确实随武魂变化，流程可继续且保存后不重复。

## BUG #9 交互式新手引导

现有引导仍以模态弹窗为主体。改为真正的聚光灯/指向气泡引导：高亮目标元素、说明与目标相邻、遮罩不阻断目标本身、本步骤需要玩家完成对应操作后再前进。至少覆盖状态面板、剧情选项、战斗入口与操作、魂环、背包/存档。找不到目标时优雅跳过或切到提示，不得卡死。

完成和跳过都必须准确调用一次后续流程；设置中提供“重新查看引导”；使用 `.status-panel` 等真实选择器；Esc、焦点管理、滚动定位和移动端位置都要正确。

## BUG #10 早期人生节点叙事

在序章与学院主线之间加入数据驱动的早期成长节点：出生家庭、幼年环境、关键人物、第一次武魂感应、入学前事件。至少按四种出身形成差异，并结合武魂类型/tier 产生分支。每段包含 2 至 3 个选择，选择能影响少量属性、关系、日记或后续文本，但不能造成新玩家不可逆死局。

这些节点要有唯一 ID、阶段与等级可达条件，并写入 `choices/doneEvents`；旧存档通过迁移标记跳过，避免打乱已有进度。

## BUG #11 升级通知侵扰

把 `onLevelUp()` 的连续阻塞 `openModal` 改为顶部非阻塞横幅队列。横幅从顶部滑入，约 2.5 秒后消失；一次经验结算连续升多级时合并成“Lv.X → Lv.Y”；若解锁魂环，附带明确提示但不阻断当前战斗/剧情。通知必须支持键盘与 reduced-motion，且不会覆盖顶部关键按钮。

验收：一次获得大量经验跨 3 级只出现一个合并通知；战斗过程中不被模态框打断；魂环待获取状态仍正确。

## BUG #12 魂环展示卡片化

将左侧 `rings-row` 的圆点升级为紧凑卡片。每项显示序号、颜色等级、魂技名、年份或来源；空槽为暗淡虚线；悬停/聚焦时右移或高亮；点击已获得魂环打开对应魂技/魂环详情。移动端折叠状态下保留简洁摘要，不挤爆状态栏。

禁止只用颜色表达年限，必须有文字或可访问标签。魂环来源缺失时显示合理兜底。

## BUG #13 战斗视觉、音效与技能播报

以 `public/game-combat.js` 的正式回合制系统为唯一核心补齐表现：普通攻击时玩家武魂向敌人方向位移或冲击；敌人受击闪烁/抖动；伤害数字区分普通、暴击、治疗；技能释放显示技能名横幅和前摇；攻击、受击、技能、胜负有程序化音效；Boss 阶段变化有清楚反馈。

动画必须由战斗状态驱动，不能延迟结算或造成重复行动；自动战斗与 1×/2×/3×速度下时序正确；关闭动画时立即结算并保留文本日志；不得依赖外部音频文件。

## BUG #14 删除突兀的命运抉择弹窗

定位 `maybeTriggerStoryDecision()` 及相关弹窗触发。移除“第一次战斗后突然弹出”等脱离剧情的强制模态选择。保留普通剧情选项自然写入 `_storyPath/_storyDecisions` 的能力；如继续展示命运值，必须在首次自然获得时用非阻塞说明解释用途：“影响部分事件和结局”，并在帮助/统计中可查看。

验收：正常游玩不会突然出现无上下文的“命运抉择”弹窗；结局逻辑不会因删除弹窗报错；旧存档字段仍兼容。

# 第二部分：38 条用户侧功能问题

## P0 阻断问题

### UX-001 引导结束后卡住

验证新游戏序章结束、引导完成、引导跳过三条路径都准确进入 `nextEvent()`。当前 `startTutorial(nextEvent)` 已有修复迹象，需补幂等保护和自动化/浏览器测试，确保回调只执行一次。

### UX-002 魂环反噬 NaN

统一使用 `finalStats().maxHp`，对风险、当前生命和计算结果做 `Number.isFinite` 防御。失败后最低保留 1 HP，保存并重载仍是有限数字。测试风险为 0、边界值、缺失旧字段与异常存档。

### UX-003 统计面板报错

验证 `getSpiritElement()`、`getActiveFormation()` 已定义且加载顺序正确；统计面板所有字段缺失时有默认值。点击统计不得出现控制台错误，数据要与真实状态一致。

## 核心战斗闭环

### UX-004 正式剧情直接判胜

所有 `result.battle` 必须进入 `BattleSystem.startEventBattle()`，不能只显示胜利文本。对手构建失败时给出可诊断错误和安全兜底敌人，但不得直接判胜。玩家可攻击、魂技、防御、道具、逃跑并可能失败。

### UX-005 经验重复结算

每场战斗奖励只能在胜利结算一次。`applyChoice()` 在战斗前不得发经验；`finishVictory()` 统一发放；失败/逃跑不领取胜利奖励。不得修改原始事件对象的 `result.exp`。移除无产品依据的全局 2.5 倍经验，或将倍率显式配置并测试。建立“配置 100 经验，最终基础获得 100×明确加成”的断言。

### UX-006 战斗统计不更新

胜利、失败、魂兽击杀、Boss 击杀、最高连击、最大伤害、使用元素、元素反应、融合、阵法使用都在单一结算点更新。区分魂师切磋与魂兽击杀，逃跑不记胜负。任务、成就、称号、统计和结局读取同一字段。

### UX-007 高级战斗机制未接主线

验证正式主线确实接入元素克制、状态、连击、暴击、自动战斗、倍速、Boss 三阶段和战斗道具。修复任何只显示 UI 但不影响数值的机制。为每种机制建立最小可重复测试或可控测试入口，生产环境不得暴露调试按钮。

## 人物、魂骨与旅行

### UX-008 人物无法自然结识

保留并增强 `recordEventDiscoveries()`：事件中出现 NPC 时调用 `meetNpc()`，优先使用结构化 `npcIds`，文本匹配仅作兼容。关键人物必须在合理主线事件中可自然解锁。避免同名误匹配。

### UX-009 NPC 首次互动冷却

首次无冷却记录时允许互动；互动后记录当前行动时间；每次世界行动推进 `_gameTime`；UI 显示剩余行动数。战斗互动和普通互动都正确写入冷却。

### UX-010 魂骨与锻造材料断开

定义清晰模型：收藏图鉴 `_bones` 代表已发现/完整魂骨，锻造消耗 `_forgeBones` 代表碎片。已有魂骨向碎片的旧档迁移只能执行一次，不能每次进游戏重复补发。战斗、挑战塔、秘境等路径能自然产出碎片，并在 UI 说明来源。

### UX-011 锻造成品不加属性

`finalStats()` 必须汇总 `_craftedBones` 的攻击、防御、生命、速度；锻造后立即刷新，保存重载后仍生效。测试多件叠加、缺失字段和旧存档。

### UX-012 旅行不能移动

旅行列表卡片可执行前往；更新当前位置、扣费、检查等级/连接/已访问条件、推进时间、写日记、触发遭遇并保存。快速旅行与普通旅行概率和费用要有明确差异。

### UX-013 地点 ID 混乱

建立唯一规范 ID，以 `map-data.json` 为准。所有中文名、`slk_academy` 等历史值通过集中别名函数迁移，不允许业务代码继续散落三套 ID。保存时只写规范 ID；加载旧档时迁移；地图、探索、旅行、隐藏地点和统计统一读取。

### UX-014 动态世界未接主循环

每次完成剧情选择、战斗、旅行、训练和 NPC 互动时通过统一 `completeWorldAction()` 推进时间、天气、冷却和隐藏地点。动态事件与连锁事件先经过 `normalizeEventShape()` 再渲染。设置合理概率与间隔，避免连续打断主线。

## 内容可达性

### UX-015 168 个武魂事件不可达

加载 `spirit-events.json` 后统一 `title→name`、字符串 `text→数组`、缺失 `phase` 推导、武魂英文键到正式武魂 ID 的映射。禁止仅按数组下标静默映射而无一致性校验；优先为武魂数据建立稳定 `eventKey`，校验每个键均唯一对应武魂。统计各武魂可达事件数并报告。

### UX-016 至少 95 个阶段等级冲突与重复 ID

扫描全部 `EVENTS`：事件的 `phase/minLevel/maxLevel` 必须有交集；冲突时按剧情含义调整阶段或等级，不能一律粗暴改 phase。重复 ID 应在源数据中修正为稳定唯一 ID，不要仅在运行时追加 `__2` 掩盖数据问题。`validate:data` 应检查重复 ID、空选项、无效 next、不可达等级区间和资源路径。

### UX-017 最终 Boss 不记录击杀

最终事件强制进入真实 Boss 战；胜利后设置 `_bossKilled`、增加 Boss 计数、完成事件、解锁关联成就/称号/结局；失败可重试；Lv.100 前不能绕过 Boss 直接结局。奖励只发一次。

### UX-018 技能点未扣除

已学习节点以对象 key 作为节点 ID；`getUsedSkillPoints()` 遍历 key 并求 cost。学习前同时检查可用点、前置与未学习；学习后立即减少显示可用点。旧数据若是数组或布尔对象需迁移。

### UX-019 技能树效果不生效

逐项落实节点说明：暴击率、暴击伤害、破甲、闪避、连击、额外攻击、回血、技能伤害、魂力消耗、冷却、攻击回魂、濒死保命、先手。没有实现的说明不得保留为虚假承诺。所有效果集中到 `_skillBonuses` 并由 `finalStats()` 或 `BattleSystem` 消费，补针对性验证。

### UX-020 阵法无效果

攻击、防御、速度阵法进入最终属性；聚灵阵进入最大魂力和防御恢复；战斗读取当前阵法；使用记录进入 `_formationsUsed`。切换后 UI 数值立即变化，保存后保持。

### UX-021 挑战塔门槛判定

所有塔层通过 `BattleSystem.start()` 真战斗，使用生命、防御、速度、元素、技能与 Boss 机制。塔层按顺序推进，奖励仅胜利后发放；失败不推进。称号奖励写入正式 `TITLES/_titles/_activeTitle` 体系，不得写孤立 `_towerTitle`。

### UX-022 成就任务称号结局不可达

列出所有条件依赖字段，建立“产生行为→统计更新→条件检查→奖励/解锁”的映射。至少修通首胜、10/50/100 胜、魂兽击杀、连击、元素、反应、Boss、融合、阵法、无败绩、金币、签到、探索等自然路径。对于当前设计中确实不存在的条件，要补玩法或调整文案和条件，不能留下永久不可达内容。

## 界面、设置和存档

### UX-023 重复商店 ID

HTML 中每个 ID 唯一，只保留一个正式商店入口或为不同入口使用不同 ID 并绑定同一函数。检查整个页面重复 ID，加入测试。

### UX-024 两套背包

所有“背包”入口统一调用一个正式实现，展示同一库存和使用规则。移除重复入口或改为同一入口的响应式镜像；旧 `openBag()` 可作为兼容包装，但不得维护两套 UI。

### UX-025 两套签到实现

仅保留一个正式 `openDailySign()`。旧函数如必须兼容应明确命名为迁移辅助且不绑定 UI，最好删除不可达重复实现。将旧 `{date,streak}` 迁移为 `{lastDate,cycleDay,totalDays,maxStreak}`，迁移只执行一次。

### UX-026 30 天签到不可达

每天首次签到增加 `totalDays`；相邻日期增加连续天数，断签重置当前连续但不重置累计；同一天不能重复领奖；维护 `maxStreak`。30 天成就读取累计天数或明确文案为连续天数，两者必须一致。日期计算使用本地日历键，避免时区跨日错误。

### UX-027 商店道具无效

狂暴丹、铁骨丹、疾风丹、解毒丹、净化符必须在正式战斗中产生与说明一致的效果；非战斗场景若不能使用，要禁用并解释，不得消耗。统一类型 `buffAtk/buffDef/buffSpd/cure/cureAll`。测试无负面状态时不消耗解毒道具。

### UX-028 设置不完整

设置至少提供：主音量、音乐、音效、文字速度、自动存档频率、战斗动画等级、粒子质量、重新查看引导、导出 JSON 文件、导入 JSON 文件。可选多存档槽若范围过大，至少不能继续承诺未实现功能。所有设置持久化并即时生效；导入前校验结构并确认覆盖。

### UX-029 M 键冲突

只允许一个 M 键行为。建议 M 打开设置，静音改用独立按钮或其他无冲突快捷键，并同步帮助。音频模块不得另行监听 M。

### UX-030 保存假成功

“立即保存”必须 await `saveServer(false)`。区分“本地和服务器成功”“仅本地成功”“全部失败”；不能请求发出即显示成功。测试服务器离线和 500 响应。

### UX-031 备份恢复未接启动

启动、继续冒险和服务器读取失败都使用 `SaveUtils.recoverFromStorage()`；主档损坏时尝试备份链，恢复后明确提示并重新写入主档。所有候选都坏时不得崩溃，提供导入或新游戏路径。

### UX-032 服务器为空忽略本地档

保存列表始终合并本地与服务器存档，服务器空列表不等于没有存档。相同 `playerId` 可合并并标识来源/时间，避免重复误导；服务器不可用时仍展示本地。

### UX-033 帮助描述不存在功能

完成前述功能后更新帮助，只描述真实可用的入口和快捷键。引导目标选择器使用真实 DOM。若某功能仍未完成，帮助中明确标为“开发中”或移除，不允许玩家以为自己没找到。

### UX-034 入口过多重复

重构信息架构而非删除功能：顶部只保留高频动作；成长、探索、收藏、系统用 `details` 分组；状态栏不再重复技能树、成就、称号入口，或仅保留清晰快捷入口。所有按钮键盘可达、移动端可操作，菜单点击外部关闭。

### UX-035 非游戏页快捷键误触

快捷键只在 `#screen-game.active` 且无模态框、无输入焦点、无正式战斗冲突时生效。切到标题、地图、图鉴、创建页后不得打开游戏弹窗或保存。处理 Ctrl/Cmd 组合，避免劫持浏览器快捷键。

### UX-036 累计金币读取余额

所有“累计获得金币”条件读取 `_totalGoldEarned`；所有正向金币入口统一走 `addGold()` 或等价统一函数并累加历史收入；消费不减少累计值。旧档至少以当前余额初始化下限。

### UX-037 称号不显示

角色名附近提供 `#sp-title` 或等价语义元素，佩戴/取消后即时刷新；无称号时不占异常空间；移动端和折叠状态可见或有可访问说明。

### UX-038 称号特殊加成无效

`gold` 加成接入所有正式正向金币奖励；`spiritPowerGain` 接入魂力上限/获取逻辑，明确是固定值还是比例，避免重复叠加。称号切换后效果立即变化，存档恢复一致。

# 第三部分：安全与后端问题

安全修复不得破坏文字 RPG 存档 API。

## SEC-001 路径遍历

当前已有 `isValidPlayerId()`，继续验证所有保存、加载、删除路径只允许安全 ID，并使用 `path.resolve` 加目录边界检查作为第二层防御。列表读取时也只接受合法文件名。补测试恶意 `../`、URL 编码、反斜杠、超长 ID 和正常 ID。

## SEC-002 安全响应头与 SEC-006 CSP

增加适合当前内联脚本/样式架构的安全响应头。若使用 `helmet`，先评估 CSP 与大量内联代码、字体和图片的兼容；不能直接开启导致游戏白屏的 CSP。优先逐步收紧，并验证所有页面资源。若暂时必须允许内联，记录原因，至少启用其他安全头。

## SEC-003 隐藏 Express 指纹

在创建 app 后调用 `app.disable('x-powered-by')`，验证响应头不存在。

## SEC-004 请求体限制

当前为 2MB。结合长期文字存档大小保留合理上限，并对超限返回清晰 413。不要盲改成 1MB 导致合法老存档失败；可通过实际最大存档和测试决定 2MB 是否合适。

## SEC-005 错误信息泄露

服务端日志保留详细错误，客户端 500 只返回稳定中文通用消息，不拼接 `err.message`、路径或堆栈。列表中的单个损坏存档不能拖垮整个列表，可跳过并记录服务端警告。

## SEC-007 外部字体

项目设计允许中文字体，但生产不应依赖无完整性控制的外部 `@import`。优先本地字体或可靠系统字体栈。若移除远程字体，保持墨金书卷视觉并避免中文字符闪烁。

## SEC-008 localStorage

离线文字游戏使用 localStorage 可以保留，不要误删。继续做好转义、存档结构校验、版本迁移和损坏恢复。任何从导入存档渲染到 `innerHTML` 的文本都必须转义。

## BUG-002 404 与错误中间件

区分前端 SPA 路由与 API 404：未知 `/api/*` 返回 JSON 404；未知静态资源不得返回 `game.html` 假装成功；仅确有需要的前端路由回退到 `game.html`。添加统一错误中间件，顺序必须在路由之后、监听之前。

# 第四部分：数据、兼容与质量要求

## 旧存档迁移

为新增/变更字段维护明确存档版本。迁移必须幂等，至少处理：地点旧 ID、签到旧结构、技能树旧结构、魂骨/碎片、累计金币、战斗统计、命运字段、事件完成 ID。禁止每次加载重复发奖励或重置进度。

## 数据一致性

扩展 `scripts/validate-data.js`，至少检查：

- 全局事件 ID 唯一。
- `phase/minLevel/maxLevel` 可达。
- `choices` 非空且 result/next 合法。
- 武魂专属事件键能映射到唯一武魂。
- 事件和图鉴图片路径存在。
- 地点 ID、连接 ID、默认位置与别名目标存在。
- 成就、任务、称号引用的统计字段有真实生产路径。
- 商店物品类型有对应使用逻辑。

## 可访问性

所有可点击卡片应使用 button 或支持键盘、焦点样式和正确 ARIA。模态框打开后焦点进入，关闭后回到触发元素；Esc 可关闭普通弹窗但不能绕过必要战斗状态。颜色不是唯一信息。正文最小字号与按钮触控区域符合项目既定要求。

## 性能

粒子、旋转、战斗动画使用 `requestAnimationFrame` 或 CSS 合成属性，避免频繁布局抖动。页面隐藏、低特效和 reduced-motion 时暂停或降级。长事件与图鉴数据不要重复绑定监听或重复加载。

## 禁止事项

- 不修改 `node_modules`。
- 不把正式入口改回 Canvas 版本。
- 不删除大量已有事件来让校验通过。
- 不通过无条件成功、无限资源、跳过战斗来修复可达性。
- 不引入 React、Vue、Tailwind 或重型游戏引擎。
- 不新增外部 CDN、远程音频或不可追溯资源。
- 不用 `setTimeout` 堆叠掩盖竞态。
- 不在生产 UI 暴露调试作弊按钮。
- 不声称“全部修复”却未逐项验证。
